# OpsPilot — Implementation Plan and Acceptance Gates

File creation alone never completes a phase. Every phase is backed by verified automated tests.

| Phase | Scope & Primary Owners | Exit Criteria | Current Status |
| :--- | :--- | :--- | :--- |
| **Phase 0: Discovery & Design** | **Rasool:** MVP scope, domain model, graph & DB plan.<br>**Mohammad:** Runtime, Compose, telemetry & CI plan.<br>**Shared:** Architecture, contracts, task board. | Core contracts, ownership matrix, and initial tasks documented and agreed. | `Completed` |
| **Phase 1: Foundation** | **Rasool:** FastAPI skeleton, Pydantic config, `/health`, SQLAlchemy session interface, unit tests.<br>**Mohammad:** Dockerfile, `docker-compose.yml` (Postgres + App), health checks, CI workflow. | Documented setup starts services; tests run cleanly; zero committed secrets; app connects to PostgreSQL. | `Completed` |
| **Phase 2: DB + Simulator** | **Rasool:** Incident/alert SQLAlchemy models, Alembic migrations, idempotent repositories.<br>**Mohammad:** Disposable e-commerce simulator service with repeatable DB pool exhaustion scenario. | Persistence survives restart; duplicate alerts do not duplicate incidents; simulator hides ground truth. | `Completed` |
| **Phase 3: Telemetry** | **Rasool:** Typed bounded telemetry tools, mocks, error/payload limits, log sanitization.<br>**Mohammad:** Prometheus, Alertmanager, scrape rules, alert rules. | Real and mock adapters satisfy identical contracts; bounded, source-attributed outputs. | `Completed` |
| **Phase 4: Investigation Graph** | **Rasool:** LangGraph state/nodes/routing (normalize → evidence → hypotheses → diagnostics → RCA), bounded retries.<br>**Mohammad:** Scenario fixtures & reset endpoints. | Synthetic alert produces structured, evidence-grounded RCA; tool failures and ambiguity handled safely. | `Completed` |
| **Phase 5: Persistence & API** | **Rasool:** Full persistence for evidence/hypotheses/reports, incident APIs, pagination, safe resume.<br>**Mohammad:** DB operational limits, health monitoring, backup/restore runbook. | Durable queryable incident history; interrupted workflows resume safely without duplicate side effects. | `Completed` |
| **Phase 6: Tracing & Evaluation** | **Rasool:** LangSmith trace correlation, labeled dataset, 8-metric evaluators.<br>**Mohammad:** Safe env/CI evaluation support. | Reproducible baseline evaluation metrics and inspectable traces when configured. | `Completed` |
| **Phase 7: Remediation & Approval** | **Rasool:** Predefined action catalog, deterministic policy engine, human approval API, execution & fresh-telemetry verification.<br>**Mohammad:** Disposable remediation target restrictions & rollback plans. | Unauthorized actions rejected; human approval enforced; recovery marked only after fresh telemetry verification. | `Completed` |
| **Phase 8: Alert Integration** | **Rasool:** Webhook ingestion, correlation, deduplication, stale/malformed alert handling.<br>**Mohammad:** Alertmanager routing, webhook auth, delivery configuration. | Controlled fault triggers Alertmanager webhook and starts repeatable end-to-end investigation. | `Completed` |
| **Phase 9: Runbooks / RAG** | **Rasool:** Runbook retrieval, source attribution, gap disclosure, prompt-injection defense.<br>**Mohammad:** Operational runbooks and human-only procedures. | Recommendations cite approved runbooks and explicitly disclose retrieval gaps. | `Completed` |
| **Phase 10: Incident UI** | **Rasool:** Incident overview, evidence timeline, approval controls, RCA report & HTML UI.<br>**Mohammad:** Grafana dashboard definition and telemetry exposure review. | Authorized operator can inspect lifecycle and approve/execute actions end-to-end. | `Completed` |
| **Phase 11: Readiness** | **Rasool:** Secret-redacting JSON logger, XSS/burst-idempotency security tests.<br>**Mohammad:** Deployment, backup/restore, troubleshooting docs, localhost port checks. | Critical paths verified, failure modes detectable, residual risks documented. | `Completed` |
| **Phase 12: Advanced** | **Rasool & Mohammad:** End-to-end scenario test, readiness verification script, and post-MVP capability ADR (`ADR-0002`). | Each advanced feature has documented rationale, risk review, and measurable acceptance criteria. | `Completed` |
